## Findings

- **L-2556 (closed in `f21d801`: disk service `do` at `/data/do`, `localDisk = "do"`, and Volumes, Rollback and Backups name `/data/do/apotheke-installation/<id>.sqlite`):** §6a *Volumes* (line 347) and §6d *Backups* (line 427) put Durable Object SQLite files under `/data/do/`, and the file-backup step copies `/data/do/` and `/data/blobs/`. The config sketch (lines 360 and 370), though, binds `localDisk` to a disk service at `/data`. Per `workerd.capnp`, workerd then writes `/data/apotheke-installation/<id>.sqlite` (a folder per `uniqueKey`), so a backup of `/data/do/` would miss the database. Fix: in the sketch, use `(name = "do", disk = (path = "/data/do", writable = true))` and `durableObjectStorage = (localDisk = "do")`. Alternatively, say the files land in `/data/<uniqueKey>/`.
- **N-2557 (closed in `f21d801`; names the 14 required before-filters plus the global ones):** Line 142 says the filter chain runs "in the order `app/Config/Filters.php` fixes (Host allow-list, base URL, session parameters, same-origin writes, permission, CSRF)". The file has 14 required before-filters (for example `opsbackup`, `api`, `routemethod`, `posttoolarge` and `consent`). The order of the six listed is right, but the list is a subset. Suggest: "…in the order `app/Config/Filters.php` fixes, including the Host allow-list, …, permission and CSRF".
- **N-2558 (closed in `f21d801`):** Line 400 reads "Not used by `apotheke-api` today (`triggers.crons` is empty on `apotheke-ops`)", which gives one Worker's config as evidence for another. Suggest: "Neither Worker uses one today: `apotheke-api` has no `triggers` and `apotheke-ops` has `triggers.crons: []`."
- **N-2559 (closed in `f21d801`; `#upgrades` resolves):** Line 425's link "upgrading and rolling back" points at the top of `deployment-and-operations.md`. Suggest `../deployment-and-operations.md#upgrades`, as line 421 already does.
