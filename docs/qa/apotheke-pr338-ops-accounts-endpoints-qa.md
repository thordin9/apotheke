## Findings

- **L-2350 (residual, accepted for now):** there's no replay nonce within the ±300 s window. A captured, signed `claim` replayed in the window mints a new token for the replayer and voids the operator's link. That stops once an admin is active, because the replay then gets 409. A replayed `reset-admins` within 300 s of a completed claim deletes the new admin and its sessions. Paired with a replayed claim, that hands over the installation. It needs a captured request from the Worker-to-container hop, since public requests always carry `X-Forwarded-*` and signing needs APP_KEY, so Low, the same as backup. Fix in PR0b or a follow-up: store the last accepted `t` per path and refuse `t` at or below it, or use a one-time nonce. Or narrow the window for these two paths.
- **L-2351:** three hardening checks have no test. Mutants that drop the 405 check, drop the 4 KiB cap or replace the exact-path match with a `/internal/accounts/` prefix all survive. Without the 405 check, a GET carrying a POST signature would run the action, because the signed method is fixed to `POST`. Everything stays behind the HMAC, so Low. Fix: add three cases to `OpsAccountsHttpTest`. A signed GET should give 405 with `Allow: POST` and no claim row. A signed 4097-byte body should give 401. Signed `…/claim?x=1` and `…/claim/` should go unanswered.
- **N-2352:** no test covers the `Services::opsAccountsEndpoint()` factory, because the tests inject the endpoint. Its hosted flag comes from `apothekeConfig`, while `FirstAdminClaim` and `HostedAdminReset` gate on `hostedLimits`, so a wrong flag gives a 500 rather than a 404. Add one test of the factory with hosted off.
- **N-2353:** the docs say "405" without its code `method_not_allowed` and `Allow: POST`, and "Self-hosted, neither exists" leaves out that self-hosted on `ops.internal` gets 421 from the host list. Name both.
- Stated residuals accepted: L-2350, the 421 when self-hosted, and that nothing reaches the endpoints until PR0b.
